# NormalMap 命名与分类规则：新版设计

日期：2026-11-15。状态：供 WB 实现的需求合同，尚未写入程序。

本规则用于 NormalMap 的新分类/导出功能，取代旧 YH 参考草案在本功能中的命名定义；不修改 素材库 内原规则、文件或索引。

## 1. 文件名

```text
种类_序号_属性.扩展名
wood_001_Basecolor.png
wood_001_Normal.png
wood_001_Height.png
wood_001_AO.png
wood_001_Roughness.png
wood_001_Metallic.png
wood_001_ORM.png
wood_001_Specular.png
```

- 种类：逐张分类弹窗中选择的标签命名值，例如 wood、concrete，也可以是用户新增的合法自定义标签。
- 序号：正整数，至少三位，不设 999 业务上限。001、002、…、999、1000、…、9999、10000 持续递增；不足三位补零，超过三位保留完整数字，不截断、不回绕。每个种类独立计数；wood_001 与 concrete_001 可同时存在。
- 属性：描述贴图用途，采用固定表，不从图片颜色或通道数猜测。
- 扩展名：按实际编码，PNG 为 .png，JPEG 为 .jpg（允许匹配 .jpeg），TIFF 为 .tif（允许匹配 .tiff）。
- 不再额外加入旧规则中的 TextureName、独立 FileID、全库 MaterialID 或 UV 方向字段。
- 文件按用户选定的导出目录保存，本期不自动创建分类子目录。

## 2. 序号对应一张源图／一套生成结果

一张源图选了 wood，分到 001，则该图生成的全部属性共用 wood_001；不是每输出一张 Normal、Height 就再加一个号。

例如 5 张新木材源图生成 20 张派生图，使用 wood_001 到 wood_005；下一张新木材源图从 wood_006 开始。水泥独立从 concrete_001 开始。

同一导入会话内给同一源图补导出另一属性，沿用已有种类和序号。新一轮重新导入默认作为新任务分配新号；跨次识别“这是以前那张材质并补图”不在本期内，不能仅凭同名文件自动复用旧号。

## 3. 属性映射

| 当前功能或数据 | 文件名属性 |
| --- | --- |
| Normal | Normal |
| Displacement 灰度高度图 | Height |
| AmbientOcc | AO |
| 粗糙度 | Roughness |
| 金属度 | Metallic |
| 固定 R=AO、G=Roughness、B=Metallic 的组合图 | ORM |
| Specular | Specular |
| 用户明确作为颜色图保存的源图副本（如以后启用该输出） | Basecolor |

Basecolor 的拼写按用户示例保留，避免混用 BaseColor/basecolor。Specular 不得标为 Roughness 或 Metallic。Height 不表示真实测量高度，沿用现有算法。

本期不因为上述示例就自动额外输出原图，不重命名磁盘原始素材，也不把任意高度图认定为 Basecolor。以后添加颜色图副本输出时使用表中字段；PNG/JPG 转换必须与实际编码一致。

## 4. 分类按钮与自定义标签

- 内置类别沿用现有分类列表，其命名值统一小写，如 Wood → wood、Concrete → concrete；按钮可显示“木材（wood）”。
- 增加“＋ 自定义标签”按钮。打开小输入框，保存成功后新增分类按钮，并给当前图片打上该标签，然后按原流程进入下一张。取消新增不打标签、不前进。
- 输入时展示“文件名将使用：xxx_001_Normal.png”的预览，使用户知道哪个值进入命名。
- 自定义标签保存到应用本机数据目录，重启仍出现在分类区；不只对本次弹窗有效。
- 标签名称直接作为命名种类。允许合法中文、英文字母、数字、下划线；英文字母统一小写，移除首尾空白；内部空格规范为下划线并在保存前预览，不静默猜测同义词或翻译。
- 不允许路径分隔符、点、冒号、通配符、控制字符等；不允许空标签。限定合理长度（建议最多 40 个字符），错误时保留输入并说明，不能点击后生成非法路径。
- 按规范化后的命名值去重：Wood、wood、首尾带空格的 wood 是同一类别。与已有内置/自定义值重复时提示并允许直接使用已有类别，不创建第二个计数器。
- 不依据显示中文名自动合并“木头”和 wood。它们是否同类由用户决定，本期不做同义词推断。
- 本期不增加标签改名、删除、合并、编号重置功能，以免历史编号失联或误复用。

## 5. 编号记忆与写入时机

- 由 Electron 主进程维护本机持久化编号库及自定义分类，不只放页面变量或 localStorage。
- 存在 app.getPath('userData') 的专用状态文件，记录 schemaVersion、规范化种类、已分配最大编号及必要的会话预留信息。界面重载、应用关闭再开、软件正常升级不应丢失。
- 不写回工程源文件、原始 YH CSV 或命名规则文档。文档是规则，状态文件才是计数器。
- 选标签、上一张、关闭分类框、取消导出目录选择不消耗编号。分类阶段可显示预估号，但必须标明尚未分配。
- 用户提交分类并选定有效输出目录后，准备写某源图第一份结果之前，主进程序列化分配并持久化一个编号，再允许图片落盘；同源图后续属性复用该编号。
- 预留成功后若导出失败或崩溃，该号保持已用，不自动回退复用。允许出现间断，优先防止重号；状态栏说明已预留未完成的任务。正常连续成功导出 5 张时，下一次严格从 006 开始。
- 状态更新采用临时文件＋原子替换等可靠方式，并对写入串行化；状态未保存成功时不能继续输出对应图片。损坏或读取失败时阻止新编号导出并说明，不能悄悄回到 001。
- 本期编号唯一性范围是同一台电脑、同一应用用户数据中的编号库。多电脑、多账户、复制便携包或手工删除编号库不具备全局同步；不能宣传“任何情况下都不重复”。

## 6. 连续扩位与重名

- 999 的下一号为 1000，9999 的下一号为 10000；初始 1–99 仍按 001–099 格式显示。界面与存储不能限制为三位数字，也不能用只匹配三位的文件名解析表达式。
- 编号库需无损保存整数；超出实现可精确表示范围时明确报错，不能因浮点精度造成重复。排序、冲突检测及恢复按数值处理，不按字符串字典序比较。
- 同一目录已存在目标名时，不静默覆盖。新源图分号时检查对应种类编号是否已经出现，必要时跳过被占用的编号；检查三位及更长的编号，不遗漏 1000、10000。
- 同一源图补导出、重复点击导出造成同名时，明确提示“跳过”或“覆盖此文件”；默认保留已有文件。不得为规避冲突私自加 (1)，因为那会违反固定命名结构。
- 主进程只在用户选定的目录写合法输出，不让分类字符串获得任意路径能力。继续保留编码/扩展名一致性、真实失败计数和不覆盖原始素材等既有约束。

## 7. 最低验收

1. 首次 wood 新源图输出 wood_001_Normal.png；其他生成属性同为 001。
2. 一次完成 5 张 wood 源图，重启后新图为 wood_006；concrete 独立从 001 开始。
3. 自定义标签保存后自动用于当前图，下一图可再次选择；重启后标签与计数均存在。
4. Wood/wood 不产生两组编号；不同源图同名不串图；中文合法自定义名可正常保存。
5. 修改上一张分类，只改变该图类别；未导出时不会消耗新旧类别编号。
6. 取消分类或输出目录不占号；持久化失败不写图；预留后异常不复用编号。
7. 实测 998→999→1000、9998→9999→10000，重启后仍正确续号；早期 1/9/10/99 分别格式化为 001/009/010/099。
8. 目标目录有已有同名时不静默覆盖；保留既有文件内容并核查实际新输出命名。
9. 最终便携包在本机跑通新规则，旧图像算法输出内容不因分类和命名改变。

## 8. ORM 打包开关与输出

ORM 固定含义，不允许在该命名下改放 Specular：

| 通道 | 内容 |
| --- | --- |
| R | AO |
| G | Roughness |
| B | Metallic |

### 按钮状态

在贴图输出选择区增加独立按钮“ORM 打包”，标明 R=AO / G=粗糙度 / B=金属度。它是可切换的导出模式按钮，不是图片类型选择项，也不在点击时立即写文件。

- 默认未启用。未同时勾选 AO、Roughness、Metallic 时呈灰色 disabled，并提示启用条件。
- 三项全勾后按钮可点，但不能自动开启；用户不点它就仍按三张单图输出。
- 用户点击后进入明确的“ORM 已启用”状态，再次点击可关闭；可使用 aria-pressed 表达开关状态。
- 启用后取消任一前置勾选，立即关闭 ORM 并灰置；再次补齐三项只恢复可点击，不自动重新开启。
- 确定生成时快照该批输出勾选与 ORM 状态，过程中不能因主界面按钮变化让同批图片采用不同打包规则。
- 三项虽已勾选但某张图实际计算失败、尺寸不一致或没有有效源数据时，该图不能输出 ORM；记录失败，不能用空白图或未经用户选择的常量假装成功。

### 文件数量与命名

同一源图、同一分类及编号：

```text
三项已选，ORM 未启用：
wood_001_AO.png
wood_001_Roughness.png
wood_001_Metallic.png

三项已选，ORM 已启用：
wood_001_ORM.png
```

打包开启时用 ORM 替代这三张单图，不额外重复导出 AO/Roughness/Metallic；其他被选中的 Normal、Height、Specular 等照常独立输出，并共享同一源图编号。不开打包就不生成 ORM。不要新增“同时输出 ORM 和三张单图”的默认行为。

本规则覆盖批量和“全部/按勾选导出”。单项 Download 仍只导出当前独立属性；若用户正在预览 ORM，则单项下载应导出 ORM，按钮文案明确当前目标，不能隐式生成一套文件。

### 数据与格式

- 打包逐像素复制最终确认的标量数据，不改变亮度、不做 gamma 转换、不用 Specular 代替任何通道，也不反转 Roughness 为 Glossiness。
- 三张源图必须对应同一源 ID 和序号，尺寸一致。全零 Metallic、全一 AO 等合法常量图可以打包，但必须是用户明确设置或真实算法结果，不能拿来掩盖失败。
- ORM 固定导出无损的实际 RGB PNG（不带 Alpha）；即使普通单图输出选 JPG，ORM 仍显示并输出 .png，提前在预览/提示说明。不得用有损 JPEG 保存 ORM 数据。
- 记录通道约定，导入引擎时作为线性数据使用，不作为 sRGB 颜色纹理。
- 粗糙度与金属度在原程序中尚无完整生成功能。用户现已确认第一版方案，按 docs/WB_ROUGHNESS_METALLIC_PLAN.md 实施；可用受控灰度 fixture 验证打包模块，但不能把 fixture 或空壳按钮当作正式功能完成。本合同不授权用 Basecolor 灰度冒充真实金属度。

### ORM 验收

1. 覆盖三项勾选的全部 8 种组合；只有全部选中时按钮可用。
2. 三项全选但不点 ORM，只输出三张单图；启用后只输出一张 ORM，文件名、像素和数量均正确。
3. 用三个不同的可核查灰度测试图，解码输出 PNG，逐像素验证 R=AO、G=Roughness、B=Metallic，PNG IHDR 为 RGB，不验证屏幕观感代替通道数据。
4. 启用后取消任何一项会关闭且灰置；重新勾全仍需用户主动开启。
5. ORM 加 Normal 等其他勾选时数量正确，均共用同一源编号；两张源图不能通道串图或各通道重复领号。
6. 尺寸不符、任一生成失败、写盘失败明确反馈，不静默降级、填通道或覆盖旧文件。
